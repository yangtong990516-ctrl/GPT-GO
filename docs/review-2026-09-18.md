# GPT-GO 整体 Review 与改进记录(2026-09-18 第二轮)

本轮对全站做了整体最终 review(后端 + 前端并行精读),并落地多项改进与修复。

## 一、架构级根治:主站数据全量 Mongo 持久化 ✅

**问题(最严重)**:主站 账号池 / 邮箱池 / 代理池 / mailcode / remail / sentinel 六个 store 全部是
in-memory mock(`internal/store/*` 仅 sync.Mutex+map),注释写着 "Mongo-backed implementation lands
when MongoDB is set up" —— 即 **Mongo 持久化从未做,所有业务数据重启即失**。连带 `mongo.NewManager`
从不 Connect,`/api/health` 的 mongo 状态恒 offline(假的);`seedMockDemoData` 每次启动注入假演示数据。

**修复**(`internal/store/mongo_*.go`):
- `mongo_base.go`:共享基座(连接/集合/单文档读写/索引)+ counters 集合自增 ID + AES-GCM secretCodec
  (`enc:v1:` 前缀,密钥托管 `metadata.secret_key`,与 icloud 同库复用同一把密钥)。
- `mongo_account.go / mongo_email.go / mongo_proxy.go / mongo_mailcode.go / mongo_remail.go / mongo_sentinel.go`:
  六套 Mongo 实现,**接口方法签名零改动**(生产用 Mongo、测试继续用 Mock)。
- 敏感字段(accessToken/refreshToken/chatgptPassword/totpSecret)加密落库、读取解密,启动时迁移历史明文。
- `cmd/server/main.go`:真实 `mongo.Connect` + `WatchHealth` 探活 → `/api/health` 的 mongo 状态真实
  (online/reconnecting);连接失败自动回退内存(warn 日志),不致命。
- 种子:`seedMockDemoData` 改为仅 `GPT_GO_SEED_DEMO=1` 时注入(默认关闭,页面打开是干净真实空状态)。

**验证**:创建账号 → 落 Mongo `accounts` 集合 → **重启服务后账号仍在**;删除正常;
`go test ./internal/...` 21 包全 ok;`/api/health` mongodb.status=online。

## 二、新增功能

### 1. 账号池批量「验活 + 查询优惠资格」✅
- 后端:`POST /api/accounts/check-combined {ids(≤100), proxyId?}`,复用已有 `plancheck.Service.CheckCombined`
  (对齐 codex check-alive/check-promotion 合并,一次同时写 alive + plan 两组字段)。Semaphore 限并发
  (上限=min(maxConcurrency,可用代理数))、claim 防重(卡死阈值自愈)、单号失败不影响其它。
  响应 `{requested,alive,dead,failed,skipped,items[{id,status,planStatus,errorCode,httpStatus}]}`。
- 前端:账号池选中后显示「验活 + 查优惠(N)」按钮,toast 汇总 存活/失效/失败/跳过。
- 说明:账号模型本就完整(totpStatus/aliveStatus/promotionEligible/subscriptionPlan/planExpiresAt/
  registrationIp 等 60 字段),详情弹窗已展示——此前缺的是「触发更新这些字段」的批量入口,现已补上。

### 2. 批量补 2FA(开通 TOTP)+ 批量查 2FA 状态 ✅
- 后端 `internal/service/accountsecurity/{mfa,service}.go`:mfa.go 底层协议(enroll{factor_type:totp}
  →兼容 {data:{}} 嵌套拿 secret+session_id→totp.Now 生成6位码→activate_enrollment,识别
  recent_auth_required);service.go EnsureOne(有密码分支:RunLogin 拿 recent_auth AT→enrollTOTP
  →StoreTotp 落库含 AT 刷新;无密码标 skipped missing_password;已有密钥标 totp_already_configured)
  + EnsureBatch(Semaphore 限流默认3,单号失败不影响其它)。
- handler:`POST /api/accounts/{id}/ensure-2fa`(单号)、`POST /api/accounts/bulk-ensure-2fa`(批量 {ids≤100});
  另 `POST /api/accounts/check-2fa`(批量查 2FA 状态,只读 /me 回写 totpStatus/mfaFlagEnabled)。
- store:AccountStore 接口 + Mock + Mongo 三处齐全 StoreTotp(totpSecret/accessToken 加密+totpStatus=enabled)
  / StoreTotpStatus。
- 前端:账号池「补 2FA(N)」批量按钮 + 账号行操作菜单「补 2FA」项 + 「查 2FA 状态」批量按钮,toast 汇总。
- 实测:空 ids→422;不存在账号→skipped account_missing;无密码→skipped missing_password。

## 五、评估后保留/列后续

- **H3(api_url 明文 token,保留)**:`mailboxAPIURL` 把邮箱 APIToken 拼进 `?key=` 返回完整取码 URL——这是
  **功能性凭据展示**(用户主动复制给脚本调用的 webhook 式链接),原项目即如此设计;改成不内嵌会破坏
  「一键复制可用链接」的核心用途。保留。
- **H1(ValidateSession 全局写锁,列后续)**:认证热路径走 `s.mu.Lock()`(写锁)+ 最长 30s Mongo 超时,
  Mongo 抖动会冻结控制台。review 自标「需复核」(收窄锁依赖 changeHub 广播顺序语义),风险高,
  不在本轮强改,列为后续性能专项。
- **前端 review 的 C1/H2/M1/M9 等**:经逐条核实均为误报(react-query invalidate 不阻塞 mutation 状态、
  icloud auth mutation 是无害死代码、console-gate 登录已正确 invalidate、版本判断逻辑 692 行已先拦截
  update_available)。前端无崩溃性 bug,Cyrillic 同形字/零宽空格 0 残留。
